# 设计卡片格式规范（必须严格遵守）

卡片是这套技能的"设计知识单元"：把"什么内容该用什么样的页面结构"沉淀成可检索、可复用、可反驳的规则。**卡片写得好不好，直接决定生成质量**。

## 一、文件位置与命名

- 位置：`knowledge/cards/<card-id>.md`（扁平目录）
- 文件名 = 卡片 `id`，kebab-case；布局骨架类卡片用 `layout-*` 前缀（如 `layout-four-grid`），内容关系类用语义名（如 `comparison-matrix`）
- 被页面计划的 `card_used` 字段引用的就是这个 `id`（不带 `.md`），校验脚本会检查它是否存在

## 二、卡片与布局模板的分工（v5.1）

| 层 | 载体 | 回答的问题 |
|---|---|---|
| 骨架 | `assets/layout-templates/*.json` | 页面分几块、各块在哪、边距与字号区间 |
| 结构规则 | `knowledge/cards/*.md` | 这类内容该用哪种结构、什么时候**不许**用 |

两者配套使用（对应表见 `cards/_README.md`）。卡片里如果写了坐标，必须与配套布局模板的 zone 一致；**不一致时以布局模板为准**，并回头改卡片。

## 三、五个必填字段（缺一个即视为不合格卡片）

YAML frontmatter 放前三个，正文放后两个：

```markdown
---
id: layout-four-grid
name: 四宫格并列
relation_type: 并列
tags: [布局, 四宫格, 并列]
---

## 适用条件
（当……时用这张卡片。写清内容特征、信息关系、模块数量与显著性，而不是"看起来好看"。）

## 反例（禁止使用）
（什么情况下**不许**用。要具体到可识别，并指向替代卡片。）

## 结构描述
（版面骨架：分几块、块宽比例、主次、标题区与内容区位置。）

## 元素与坐标
（关键元素的建议坐标与尺寸，单位英寸，基于 13.333×7.5in 画布，且与配套布局模板 zone 对齐。）

## 变体（可选）
（同一结构在别的场合怎么微调。）
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 必填、唯一、与文件名一致 |
| `name` | string | 必填，中文短名（≤ 8 字） |
| `relation_type` | enum | 必填：`比较` / `流程` / `层级` / `因果` / `时间` / `并列`，或 `通用`（与信息关系无关的骨架/封面类卡片） |
| **适用条件** | 正文段 | 必填，正向筛选条件 |
| **反例（禁止使用）** | 正文段 | 必填，负向排除条件。**只写外观描述的卡片直接不合格** |

`tags`、`结构描述`、`元素与坐标`、`变体` 建议写全；缺「元素与坐标」会导致生成时坐标靠猜、越界率上升。

## 四、写作要求

1. **写判断依据，不写审美形容词**。"清爽""大气"没有信息量；"四段并列且无主次时用"才有。
2. **反例必须具体到可识别**：写"对象 ≥ 3 时禁用本卡片，改用 `comparison-matrix`"，而不是"不适合复杂内容"。
3. **反例要指向替代卡片**，让模型知道被排除后去哪。
4. **一张卡只解决一类问题**；卡片名带两个主题说明该拆。
5. **坐标给区间**（如 `x: 0.8–0.9in`），给死值会导致不同页呆板。
6. **卡片总量 8–12 张**：新场景优先扩展现有卡片的变体，确实不同再新建。

## 五、校验方式

```bash
python scripts/validate_plan.py output/plan.json --knowledge knowledge
```

脚本会扫描 `knowledge/cards/`：`id` 与文件名不一致、`relation_type` 非法、缺"反例"段落、`id` 重复都会报错。新建/改完卡片先跑一次。

## 六、从失效案例升级为卡片

终审发现"某类内容反复被排错"时按顺序处理：

1. 先写 `knowledge/fail_cases/`（记录现象与场景）；
2. 同类案例第二次出现 → 判断是否现有卡片边界不清：是则改卡片的适用条件/反例；
3. 只有现有卡片都覆盖不了新结构时，才新建卡片（并同步确认配套布局模板是否要补）。

不要一遇到问题就新建卡片，那会让卡片库互相覆盖、检索失效。
