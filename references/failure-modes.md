# 失败模式自检（8 种）+ 密度模式 + 图表匹配 + Bento 卡片

对应规格 v7.5 验收项：失败模式自检、两种密度模式、图表自动匹配、Bento 卡片布局。
**生成前逐条对照**；命中即先改页面计划，不要靠构建脚本兜。

## 一、8 种常见失败模式

| # | 失败模式 | 症状 | 怎么检出 | 修法 |
|---|---|---|---|---|
| 1 | 风格漂移 | 同一稿出现两套色/字/图标风格 | `validate_plan.py` 的卡片/图标校验；人工抽查两页色值 | 锁死 `visual_system`，装饰与图表都取该系统色 |
| 2 | 极简偷懒 | 内页只有几行字、大面积白灰 | `validate_plan.py` 密度模式检查（vivid 下限 6 个元素）；`score_deck.py` 密度分项 | 按 `density_modes.vivid` 补足**与内容相关**的模块/指标/图表 |
| 3 | 图片拼装 | 内页 0 文本框、整页图片 | `detect_layout.py` 原生核对的 notes/charts/tables；人工看是否为 0 文本对象 | 正文/标题/图表/表格改原生对象；整页图只作背景层 |
| 4 | 数据不可编辑 | 图表是截图、表格是形状拼 | `detect_layout.py` 原生对象核对（charts/tables 计数） | 改用原生 Chart / Table（红线第 2、3 条） |
| 5 | 假密度 | 为凑元素数加无关装饰 | 人工核对"纯装饰元素 ≤ 元素总数 1/3" | 删无关装饰，换成与论点相关的内容元素 |
| 6 | 标题空泛 | 标题是"项目背景"这类栏目名 | `validate_plan.py` 行动标题检查（黑名单 + <8 字） | 改成完整结论句（见 `narrative.md`） |
| 7 | 备注缺失或敷衍 | 备注为空或 <20 字 | `validate_plan.py` 备注检查；`detect_layout.py` notes_nonempty | 按"主张/卡片理由/素材/讲述提示"四段补写 |
| 8 | 排版塌陷 | 元素越界、文本溢出、互相遮挡 | `detect_layout.py` 的越界/溢出/遮挡三类检查 | 调坐标或删减内容；不要靠缩字号硬塞 |

## 二、两种密度模式（`design_brief.density_mode` 二选一）

| 维度 | `concise` 简洁版 | `vivid` 高级耀眼版（国赛取向，v8.0 加严） |
|---|---|---|
| 内页元素数 | 3–5 | **6–10 个有效元素** |
| 有效元素定义 | — | 必须与内容相关（数据/论点/图表/图片）；纯装饰性线条/边框/图标 **≤ 元素总数 1/3**，不得凑数 |
| 留白 | 大留白、低饱和可接受 | 禁大面积纯白/纯灰、禁低饱和"莫兰迪" |
| 图片 | 可选 | **每页 1–2 张**（产品图/场景图/人物图/数据图），不能全是纯文字页 |
| 篇章导航 | 无要求 | **每页顶部必须有篇章导航标签栏**，不能光秃秃直接放标题 |
| 大字号数据 | 可选 | **至少 1 个 36–60pt 大字号数据**，作为本页视觉焦点 |
| 卡片精致度 | — | 所有内容卡片必须有**细金边/主题色边框 + 轻微投影 + 左上角序号**，不得是光秃秃的白方块 |
| 标题 | 可用栏目名 | **大标题下必须配装饰线**；国潮/红金风格默认用**飞白书法 PNG** |
| 背景 | 纯色可接受 | **不得纯白/纯平**：需渐变、纹理或淡淡装饰纹样 |
| 红线 | — | 红线 19/20/21/22（19/20 仅约束高级耀眼版）：禁止"素"、禁止自动极简、禁止短剧式标题、禁止正文 AI 味（21 的党建/政务正式表达、22 的党建/政务/乡村振兴升华结尾按豁免处理） |

校验落点：上述硬指标写在 `config.json:density_modes.vivid`，由 `scripts/validate_plan.py` 逐条给出 warning
（装饰占比 / 装饰层缺失 / 无 36pt 以上大字 / 图片数量 / 是否用带导航的版式 / 纯白背景提示）；
卡片边框与投影属渲染效果，构建脚本按 `pptxgenjs-config.js` 的卡片样式统一施加，静态校验只查结构与数量。

## 三、图表类型自动匹配（按数据语义选型）

| 数据要表达 | 用哪种图表 | 备注 |
|---|---|---|
| 随时间变化（趋势） | `line` | 标签写年份/阶段 |
| 类别之间比大小（对比） | `column`（竖）/ `bar`（横） | 类别多于 6 个用横向 `bar` |
| 部分占整体（占比） | `pie` / `doughnut` | 类别 ≤5，且数值之和=100% |
| 排名 | `bar`（横向，降序） | 突出第一名用 `highlight_index` |
| 构成随时间变化 | `column`/`bar` 堆叠 | 系列 ≤3 |

要求：分类名必须是业务名（不得出现 1/2/3 这类序号）；重点数据用强调色，其余用灰；
轴标签/数据标签/图例 ≥11pt；单图系列 ≤3（见 `native-objects.md`）。

## 四、Bento 卡片布局

- 每页**至少 3 张内容卡片**，内容驱动版式（卡片装内容，不是装装饰）；
- 卡片 3–6 张为宜，超过 6 张说明本页该拆；
- 卡片**等大或按信息量分主次**（1 主 + 2–4 次），主卡放核心结论/指标；
- 卡片内结构一致：图标 + 小标题 + 2–3 条要点；
- 落点：`layout-templates.md` 的 `four-grid` / `sidebar-nav` 版式与 `knowledge/cards/` 的 `layout-four-grid` / `layout-sidebar-nav`。

## 五、自检顺序

```bash
python scripts/validate_plan.py output/plan.json --knowledge knowledge   # 计划层：密度/标题/风格理由
node   scripts/build_pptx.js --plan output/plan.json --candidate A --out output/deck.pptx
python scripts/detect_layout.py output/deck.pptx --json output/detect.json # 排版层：越界/溢出/遮挡/原生
python scripts/score_deck.py --plan output/plan.json --candidate A --deck output/deck.pptx  # 打分与最弱页
```
