# 已知坑与禁止行为清单（v5.1）

每次生成**开始前**扫一遍；生成后发现新坑，按格式补进来（而不是只记在心里）。

## 一、路线级红线（违反＝返工）

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | HTML 渲染再转 PPTX | 产物是图片，不可编辑 | 只用 PptxGenJS 原生对象 |
| 2 | 图表用图片贴 | 数据不可改，改数要重做图 | 原生 `addChart`，带数据源 |
| 3 | 表格用矩形+直线拼 | 改单元格要重画 | 原生 `addTable` |
| 4 | 用 PowerPoint COM 自动"修复"排版 | COM 进程易挂起 | 只检测、只报告，人工改 |
| 5 | 模型自由选字体/配色 | 换机错版、整份花掉 | 全部取自视觉系统 |
| 6 | 每页都生图 | 成本高、风格漂、重点稀释 | 3–5 张/份 |
| 7 | 自实现生图或本地画图 | 与 DSH 生图能力重复 | 调 DSH 生图插件 |
| 8 | 引入云知识库/向量库 | 违背本机部署前提 | 全部落 `knowledge/` |

## 一·续、标题表达（v8.4 红线第 21 条：禁止短剧式标题）

| 坑 | 为什么不行 | 正确做法 |
|---|---|---|
| 标题写成"金句"（我最怕的是… / 凭什么 / 没人告诉你） | 像短剧台词，不像汇报，评委直接判不专业 | 直接给结论与事实：「延期 2 周，风险集中在物料交付」 |
| 标题里带第一人称情绪（我怕 / 我哭过 / 我熬过） | 情绪化且信息量低 | 换成客观陈述 + 数据 |
| 标题用口号式反问或感叹（真的吗？／谁说的？／别急） | 悬念式表达占着标题位却不传递信息 | 标题只承担"这一页的结论" |
| 封面 / 结尾页用文学化短句包装 | 允许留主题词的位置也不能情绪化 | 封面用项目名 + 定位；结尾用致谢 / 总结句 |

判据与改法见 `narrative.md` §二·1；`validate_plan.py` 命中 `config.json:narrative.cliche_title_patterns` 给 warning（党建 / 政务类项目的正式政治表达命中 `cliche_exempt_patterns` 时不判为短剧金句，如「凝心聚力促振兴」），
`score_deck.py` 的「叙事与正文」分项一并扣分。

## 一·续二、正文语气（v8.6 红线第 22 条：禁止 AI 味）

| 坑 | 为什么不行 | 正确做法 |
|---|---|---|
| 用小红书 / 短视频口吻写正文（家人们、绝绝子、谁懂啊、快收藏） | 与竞赛/评审场景的正式度不匹配，像营销号 | 客观陈述 + 数字：「试点三项指标高于基准线」 |
| 一行一句、短句堆叠 | 读起来像文案脚本，不是汇报 | 合并成完整句，用逗号/分号串联逻辑 |
| 每段结尾都升华（未来可期、我们坚信、携手共创） | 空洞表态挤掉信息量 | 结尾落在事实、结论或下一步动作 |
| 空泛动词堆砌（赋能 / 打造 / 构建 / 引领）混用 | 科技/商业类项目里等于什么都没说 | 换成可核对的动词与数字 |
| 把党建 / 政务 / 乡村振兴语境里的正式政治语言当"AI 味"删掉 | 误伤：这些词在该语境属正式表述 | 按语境判定（`config.json:body_style.context_exempt_keywords`）保留 |
| 把党建 / 政务类标题里的正式政治表达当「短剧金句」删掉 | 误伤：「凝心聚力促振兴」是规范表达 | 命中 `narrative.cliche_exempt_patterns` 时不判为短剧金句 |

判据、正反例与豁免规则见 `narrative.md` §二·2；`validate_plan.py` 命中三份词表给 warning / info（党建 / 政务 / 乡村振兴语境的升华结尾按 `escalation_exempt_in_context` 视为规范表达），
`score_deck.py` 的「叙事与正文」分项一并扣分。

## 二、图层与堆叠的坑（v5.2）

0-a. **元素不写 `z_index`**——绘制顺序变成"按计划里的书写顺序"，改一处顺序就可能让装饰压住文字。每个元素都必须声明。
0-b. **装饰 z_index 排到内容之上**（例如把色带写在 25）——校验会直接报 error；装饰一律 10–19。
0-c. **用 `z_index: 0` 的元素去模拟页面背景**——背景层（L1）由母版与 `image_path` 处理；写成元素会导致背景被后续元素反复覆盖、且无法被蒙版统一控制。
0-d. **标题层忘了抬高**（标题 z=20 与内容同层）——内容后绘制就会盖住标题；标题一律 ≥ 30。
0-e. **靠"看起来在上面"手工调顺序**——不要用调顺序代替分层声明，脚本按 `z_index` 升序绘制，手调无效。
0-f. **装饰层完全不透明还压在图上**——L2 素材透明度按视觉系统 50–80%，且不得遮住文字可读性（对比度 ≥ 4.5:1）。

## 二·续、构思阶段的坑

1. **三个及以上对象对比却用双栏**——`layout-two-column` 反例明确"对象 ≥ 3 禁用"，改用 `comparison-matrix`（验收点名的场景）。
2. **3 个对象硬凑四宫格**——四宫格要求四格等大；3 个对象改 `data-dashboard` 的 3 卡布局。
3. **A/B 两套只改配色措辞**——差异必须落在结构（布局与顺序）上。
4. **`section_name` 与 `design_brief.sections` 对不上**——导航会高亮错章节。
5. **给不存在的卡片/图标/模板硬填 id**——校验会拦，且污染后续生成。
6. **`relation_type` 默认套"并列"**——判断不了就问用户。
7. **一页塞多个 claim**——一页只承载一句话，塞不下就拆页。
8. **高密度＝堆满**——模块数超视觉系统上限就是信息没收敛，先删信息。

## 三、素材与配图阶段的坑

9. **prompt 里要求生成文字**——图里的文字不可编辑、易乱码。
10. **prompt 出现写实人物**——版权与焦点风险。
11. **同一份 PPT 混用风格预设**——封面商务、章节页科技，观感割裂。
12. **封面图没有留白**，标题压在高亮区看不清；**首轮视觉校验实测**：白字压在中灰蓝底（对比度约 3.2:1）投影会发灰，蒙版透明度要提到 55–70。
13. **两个章节页用风格差异明显的两张图**——同类页观感不统一，建议复用同一次生成、同一 prompt 前缀的图。
14. **大面积强调色**——accent 单页占比 ≤ 5%；整条漏斗用橙色块会与"商务克制"基调冲突（首轮校验结论）。
15. **透明底特效图返回实底还硬叠**——改用原生降级实现。
16. **数据页配图**——数据页用原生图表，图会变成不可改的像素。

## 四、构建与排版阶段的坑

17. **文本超框溢出**——中文按 `w_in×72÷font_pt` 估字/行，留 20% 余量。
18. **元素遮挡**——色块与文本错位；元素间 ≥ 0.05in 间隙。
19. **字号过小**——正文 < 12pt 基本不可读；首轮校验发现 13–14pt 远距投影偏小，正文建议 14–15pt、标题 24pt 起。
20. **标题换行超 2 行**——压缩文案或加大 `w_in`，不要缩字号硬塞。
21. **图表分类显示成 1/2/3**——**首轮视觉校验确认的必改项**：坐标轴类别与图例必须是业务名；生成后必须抽查渲染图确认。
22. **图表系列长度不一致**——`labels` 与每个 `series.values` 必须等长。
23. **纯色降级后忘换文字颜色**——深底配深字＝看不见。
24. **把图片当形状用**（装饰线、色块、图标）——用原生 shape/icon。
25. **底部留白过大**——内容止于页面中上部、底部空 30%+ 是本包首轮校验最常见的观感问题；内容块应整体垂直居中。
26. **同类页面标题位置漂移**——同类页标题必须同一个 y 值。
27. **表格数字列不右对齐**——视觉校验会判为不一致。

## 五、流程与协作的坑

28. **跳过 `validate_plan.py` 直接构建**——字段错误会变成莫名其妙的崩溃或错版。
29. **不检索 fail_cases 就构思**——命中过的同类问题会再犯。
30. **终审发现严重错误却不回写**——这套技能就失去了"越用越准"的能力。
31. **对用户隐瞒问题**——降级、特效失败、检测出的问题都必须如实说明。
32. **夸大能力**——不要声称达到"设计师级/金奖级惊艳感"；能做到的是国金参考图的 70–80%，最后 10–15% 靠人工。**复杂排版公式**同样不承诺由脚本生成。

## 深色视觉系统必须自带 surface 颜色键（v8.8 踩坑）

`resolveToken()` 的解析顺序是「先查视觉系统 `colors`，再回落到 `config.theme`」。而 `config.theme.background` 是**白色**——若一套深色视觉系统没有 `surface` 键，任何用 `surface` 的卡片都会被画成「半透明白」（实测渲染成中灰 `RGB(154,152,150)`），卡内白字直接不可读。

- 已在 9 套深色系统补齐 `surface`（取 `primary`）：`tech-gold-noir` `#1F1B16`、`tech-dark` `#0f2f3f`、`tech-deep-blue` `#0D47A1`、`tech-teal-green` `#004D40`、`ref-airflow-medical-blue` `#0F314C`、`ref-blackgold-tech` `#B7472A`、`ref-chip-industrial` `#CE8140`、`ref-medical-blue` `#0E419C`、`ref-typo-closing` `#44546A`；
- 新增视觉系统时必须同时给 `surface` 与 `text_light`，否则卡片/次要文字会落到浅色主题值；
- 同理，深色系统里 **`primary` 是深色**，不要把标题的字色写成 `primary`（会与深色底同色而不可读）——文字用 `text` / `text_light`。

## 六、形状与轮廓（v9.0.3 新增）

33. **形状当装饰凑精致**——圆角＋渐变＋语义小图标（奖杯·向日葵·灯泡）能让人显得「努力做了」，但恰好是模板味的配方；国赛／对外场景按减分处理，规则见 `shape-language.md` §四。
34. **一册混用多套轮廓**——同一份稿子里圆角、切角、弧形混排＝拼贴＝AI 味来源；一份稿子只允许一套轮廓语法，圆角半径全稿同值。
