# 跨客户端兼容规范（WPS / Office / Mac）（v8.9 新增）

目标：同一份 `.pptx` 在 Windows + Microsoft PowerPoint、WPS Office、macOS PowerPoint 上打开时，版面与字体尽量一致。
本包不承诺"三端像素级一致"，只做**能静态验证的规避**，并如实标注做不到的部分。

## 一、四类已知差异（来源：CSDN《PptxGenJS 布局兼容性问题》，中等可信度）

| 差异 | 表现 | 根因 |
|---|---|---|
| WPS 文本框偏移 | WPS 下文本框整体位移几毫米 | 依赖"自动调整/自动缩放"，WPS 与 PowerPoint 的缩放置信区间不同 |
| Office 2016 图片拉伸 | 图片被压扁或拉长 | 只给框宽高、不给等比约束 |
| Mac PowerPoint 表格边框消失 | 表格线看不见 | 边框色取自主题默认，Mac 主题缺省不同 |
| 字体回退 | 换一台机器字体就走样 | 只声明拉丁字体（`<a:latin>`），东亚字体未声明 |

## 二、本包的规避（现状 + v8.9 新增）

| 差异 | 本包做法 | 状态 |
|---|---|---|
| WPS 文本框偏移 | 文本框一律固定 `w_in/h_in`、`margin: 0`、`isTextBox: true`，不依赖自动缩放；`detect_layout.py` 的文本溢出/遮挡检查兜底 | 既有 |
| Office 2016 图片拉伸 | **v8.9 修复**：`addImageFitEl()` 改为一律按原始宽高比放置（contain）——图片更宽时按框高缩宽居中、更窄时按框高缩宽并补两侧渐变；此前"图片更宽"分支把框尺寸直接交给图片，比例不符即被拉伸 | 新增修复 |
| Mac 表格边框消失 | 表格边框**显式**给色（`vs.colors.text_light`）与线宽 `0.5pt`，不依赖主题默认 | 既有 |
| 字体回退 | 字体只走 `config.fonts.whitelist`（微软雅黑 / 思源黑体 / 黑体 / Arial…），`resolveFont()` 只放行白名单；**v8.9 实测**：PptxGenJS 已自动为中文同时写 `<a:latin>` 与 `<a:ea>`（示例稿 212 : 212，见构建日志「字体声明」行），XML 后处理另加一段**幂等兜底**——某段若只有拉丁声明则补 `<a:ea>`/`<a:cs>`（插在 latin 之后，符合 DrawingML 子元素顺序） | 实测确认 + 兜底 |

## 三、交付时固定附一句提示

> 本稿做过静态兼容检查（文本框固定尺寸、图片等比、表格显式边框、东亚字体声明）。若在他人电脑上字体有差异，请安装白名单字体（微软雅黑或思源黑体）。

## 四、校验落点

| 脚本 | 检查 |
|---|---|
| `validate_plan.py` | 计划出现的字体必须在白名单；图片元素的宽高比与源图偏差超限给提示 |
| `build_pptx.js` | 图片等比放置、表格边框显式色；构建日志输出 latin / ea / cs 字体声明统计与兜底页数 |
| `detect_layout.py` | 文本溢出、越界、遮挡（版面级兜底） |

## 五、边界（明确做不到的）

- **不做**真机逐客户端目检：本机只装 Windows PowerPoint，差异清单来自公开资料 + 本包静态检查，因此不承诺"三端一致"；
- **字体可用性取决于目标机器**：白名单字体未安装时系统会回退到它自己的默认中文字体，本包只能保证"已声明东亚字体"，不能保证外观完全相同；
- 第三方模板/主题文件（若用户自带）不在本规范的覆盖范围。
