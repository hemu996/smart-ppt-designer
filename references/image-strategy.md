# 配图策略（生图 / 图库 / 图标三级降级）

本文件替代早期版本的"配图生成策略"，新增图库层与图标层。原则一句话：**核心内容原生可编辑，装饰与氛围用图片，且图片要有节流。**

## 一、缺图补齐优先级（v9.0.3 修订，用户 2026-11-08 指定）

用户口径原话：「如果缺少图片的话，就用 AI 生成。但是 AI 生成必须是符合我们这个 PPT 主题的，而且是能够融入这个 PPT、不会让他显得突兀的，或者甚至可以用 PPT 原本的那些封面图片那些。」

**核心变化：缺图时先补图，不要直接退到纯色背景。** 补图按下面顺序取，越靠前越优先：

| 顺序 | 来源 | 什么时候用 | 说明 |
|---|---|---|---|
| **0（最优先）** | **复用本稿既有图** | 本份 PPT 已有封面图 / 章节图 / 之前生成的图 | 直接取现成的，**最不容易突兀**：同一份稿子的图天然同风格、同色系。可按页复用同一张（允许重复，不要为了"不重复"硬造新图） |
| **1** | **AI 生成补图** | 没有可复用图 | 必须满足下方「融入三判据」，不是随便出一张贴上去 |
| 2 | 免费图库 | AI 生图失败/被拒，且有 API Key | 需记录来源与授权 |
| 3 | 纯色背景 | 以上都不可用 | **只作为最后兜底**，且必须在交付说明写明"第 X 页退到纯色" |

- 顺序 0 与 1 同属"补齐图"，不算降级；只有 2、3 才记 `info` 降级。
- **降级不阻塞流程**（红线第 15 条）：但「缺图 → 纯色」不再是默认答案，要先问「能不能复用本稿的图 / 能不能按主题补一张」。
- `config.image.on_failure` 由 `solid_color` 改为 `reuse_then_generate`（见 config 注释）；纯色仍是最终兜底。

### 融入三判据（AI 补图必须同时满足，否则重生成）

> **封面人物形象替换**（模板封面里的人不对）另见 `references/cover-persona-swap.md` 五步法：
> 读图 → 拆人物描述 → 归类 → 用类别文案生成 → **保同级效果**。
> 补的第五条硬要求：**视觉级别必须与原图同档**（摄影↔摄影、插画↔插画），
> 人物类别对了但级别降了，比不换更糟。

"符合主题、能融入、不突兀"不是形容词，落成三条可核查的要求：

1. **主题对应**：prompt 必须写明**这一页讲什么**（用本页 `claim` / `section_name` / 关键名词），
   禁止用"科技感背景""商务抽象图"这类通用装饰图。V12 已有的口径继续有效：每页图对应本页主题，不做通用装饰图。
2. **风格续用**：必须与本稿既有图**同一套视觉语言**——同一 `visual_system` 的 `image_style` 前缀、
   同一色系（亮底/深底一致）、同一质感（写实 / 插画 / 水墨 / 线稿不混）、同一留白方位。
   若本稿已有封面图，补图应描述成"与封面同一张图的延伸 / 同一场景的另一角度"，
   而不是另起一套画风。
3. **不抢戏**：补图只做背景 / 氛围 / 概念承载，**画面内不出现文字、不出现写实人物**；
   主体与文字区保持留白；需要时叠与封面同款蒙版，保证文字对比度 ≥ 4.5:1。

### 判定方式（必须做，不能凭"我觉得挺搭"）

- 补图后要**渲染该页 PNG 目检**：把补图页与相邻已有图页并排看，
  色系 / 质感 / 明暗 / 留白方位明显不一致 → 判为突兀，重生成或改回顺序 0 复用。
- 交付说明里写明：哪些页复用了本稿原图（哪一张）、哪些页是 AI 补的（prompt 主题句）、
  哪些页退到图库 / 纯色，以及并排目检结论。
- 复用同一张图不算偷懒：**重复是融入，乱换才是突兀**。

## 二、什么页要图

| 页面 | 是否要图 | 类型 |
|---|---|---|
| 封面 | ✅ 必 | 背景大图（生图优先） |
| 章节过渡 | ✅ 必 | 意境背景 |
| 概念页 | ✅ 选（≤ 2 页） | 半版插图 |
| 数据页 / 内容页 | ❌ | 用原生图表、形状、图标 |
| 结尾页 | ⬜ 选 | 简约背景 |

预算：**3–5 张/份**（红线第 6 条）。超出时先砍概念插图。

## 三、prompt 公式（脚本执行，模型不手写）

```
封面   = <视觉系统 image_style 的 style_prompt>，"<主题意象>"，<background_prompt>，<留白方位>，画面内不出现任何文字，不出现写实人物
章节页 = 同上，主题意象换成"<章节名的概念意境>"
概念图 = <illustration_prompt>，"<概念描述>"，浅底，右侧留白，画面内不出现任何文字，不出现写实人物
结束页 = 同上，主题意象换成"收束、留白、简洁"
补图   = <本稿既有图的风格前缀> + "与封面/第 X 页同一场景、同一色系、同一质感" + "<本页 claim 的具体意象>" + <留白方位>，画面内不出现任何文字，不出现写实人物
```

- **补图 prompt 必须显式带上"与本稿既有图同一套"的约束**（顺序 1 的判据 2），
  且主题意象取自本页内容，不用通用装饰词；
- 留白方位必须与标题/内容位置一致；
- **不要生成文字**（文字一律原生文本框叠加）；
- **不要写实人物**（版权与焦点风险）；
- 同一份 PPT 的所有 prompt 共用同一风格前缀（红线：风格统一）。

## 四、图库层（免费图库）

- 接口与字段见 `integrations/free-photos.md`；Key 走环境变量（`PEXELS_API_KEY` / `PIXABAY_API_KEY`），**不写进配置或代码**；
- 只用免费授权图片，且在交付说明中记录**来源链接与授权类型**；
- 图库图作为背景时同样要叠蒙版，保证文字对比度 ≥ 4.5:1；
- 无 Key 时直接跳到第三级，不要尝试抓取未授权图片。

## 五、图标层（不是图片）

图标用内置 `assets/icon-library/icons.json` 的**原生形状组合**绘制，不占生图/图库预算，也**不得**用图片贴图标。使用方式与节流规则见 `assets/icon-library/_README.md`。

## 六、尺寸与命名

| 用途 | 尺寸 |
|---|---|
| 封面 / 章节页 / 结尾页 | 1920×1080 |
| 概念插图 | 800×600 |

文件命名 `slide_{id}_{image_type}.png`，放 `output/images/`；`generate_images.js --fill` 会把实际路径写回页面计划的 `image_path`。

## 七、失败处理

1. 单张最多重试 2 次（间隔 1.5s）；内容违规类拒绝**不重试**，改中性描述后重提一次；
2. 仍失败 → 降级到图库；图库也不可用 → 纯色背景；
3. 交付说明必须写明降级页码与原因；
4. 只重生成某一页：`node scripts/generate_images.js --plan … --only-slide <id>`。

## 八、禁止事项

- ❌ 自实现生图或本地画图代替（红线第 7 条）；
- ❌ 每页都配图；
- ❌ 模型临时手写 prompt（风格会漂）；
- ❌ 用未授权图片、或把带水印的图放进 PPT；
- ❌ 把整页（含文字）做成一张图。
