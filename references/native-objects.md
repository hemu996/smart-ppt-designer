# 原生对象规范（母版 / 图表 / 表格 / 公式 / 备注）

"原生深度"是本技能包与"图片拼 PPT"的分界线。**验收时会真的去 PowerPoint 里改数据、改单元格**，所以这里列的每一条都要在产物里成立。

## 一、母版与版式

`build_pptx.js` 用 `pptx.defineSlideMaster()` 定义 5 个母版：

| 母版名 | 用于 | 母版内容 |
|---|---|---|
| `COVER` | 封面 | 背景层、标题占位、信息行占位（无导航） |
| `SECTION` | 章节过渡 | 背景层、章节标题占位（无导航，或仅顶部进度） |
| `CONTENT_NAV` | 内页 | **侧边栏章节导航**（当前章高亮）+ 页脚页码占位 |
| `DATA` | 数据页 | 同 CONTENT_NAV + 指标卡/图表/表格区参考线 |
| `CLOSING` | 结尾页 | 背景层、致谢占位（无导航） |

说明：PptxGenJS 的 `defineSlideMaster()` 实际产出的是**同一母版下的自定义版式（slideLayout）**——验证时应在 `ppt/slideLayouts/` 下查到 COVER / SECTION / CONTENT_NAV / DATA / CLOSING 对应的版式，`ppt/slideMasters/` 下至少 1 个母版。交付说明里写"母版/版式"更准确。

要求：

1. 版式必须真实存在（`ppt/slideLayouts/` 与 `ppt/slideMasters/` 下可查），不是"看起来像"；
2. 导航栏内置于母版，**不是每页手工画**——内页统一从 `CONTENT_NAV`/`DATA` 版式生成；
3. 当前章节高亮：按 `design_brief.sections` 与页面 `section_name` 匹配，命中项用 `navigation.active_color` 填充 + 白字，其余用 `inactive_color`；
4. 封面、章节页、结尾页**不加导航**（否则观感混乱）。

## 二、原生图表（红线第 2 条）

- 一律 `slide.addChart(pptx.ChartType.*, data, opts)`；数据以 `{ name, labels, values }` 传入，pptxgenjs 会把数据源写入图表工作簿 → **在 PowerPoint 里可以"编辑数据"**；
- 禁止把图表截图当图片贴；
- 图表配色只用视觉系统 `chart_palette`；
- 轴标签、数据标签、图例字号 ≥ 11pt；分类名必须是业务名（如"医院集中式"），**不能出现 1/2/3 这类无意义序号**；
- 图表框内不要放过多系列：柱/条 ≤ 3 系列，折线 ≤ 3 条。
- 首轮视觉校验发现的必改项：**坐标轴类别与图例必须显示业务名称**。生成后要用 `detect_layout.py --json` 或人工抽查确认；若渲染端把类别显示成序号，改数据组织方式（分类名写入 `labels`，不要依赖默认序号）后重出图复查。
- **图表配色规范（v8.3 四条）**：
  1. **同一系列**数据：用**同一颜色的深浅渐变**，不要另起色相；
  2. **对比系列**：用 `primary` 与 `accent` 成对出现；
  3. **重点数据**（要突出的那个）：用 `accent`，其余用灰；
  4. **层级**：图表标题用 **H4 层级（16–18pt）**，数据标签用 **Caption 层级（10–11pt）**。
  落点：配色只能取视觉系统 `chart_palette`（红线第 5 条），重点突出用页面计划里 `chart.highlight_index` 指定。

## 三、原生表格（红线第 3 条）

- 用 `slide.addTable(rows, opts)`，行列数据来自页面计划的 `table` 元素；
- 禁止用"矩形 + 直线"拼表格；
- 表头用 `primary` 底色 + 白字；斑马纹用同色 8% 透明；单页表格 ≤ 6 行 × 5 列；
- 单元格字号 ≥ 10pt，数字右对齐、文本左对齐（数值列必须对齐，否则视觉校验判为不一致）。

## 四、公式

- 简单公式（求和、比例、上下标）用**原生文本框 + Unicode 数学字符**表达（∑ ∫ √ ≈ ≤ ≥ ± × ÷ ² ³ ₁ ₂），保持可编辑；
- 复杂排版公式（分式、矩阵）**不在脚本里硬做**：在页面计划里用 `type: "formula"` 标注位置与文本，构建后由人工在 PowerPoint 公式编辑器中替换（脚本会输出待替换清单）。
- 这是**诚实的边界**：Flash 模型 + PptxGenJS 不承诺生成主编排公式，不要声称已支持。

## 五、讲者备注（红线第 14 条）

- 每页都要有 `slide.addNotes(...)`（`config.json` 的 `notes.required = true`）；
- 备注内容四段：**页面主张（claim）→ 选中卡片与理由 → 背景/素材说明 → 讲述提示（一句怎么讲）**；
- 构建脚本默认写入备注，**不需要额外开开关**；
- `detect_layout.py` 会检查每页备注是否非空，缺页报 `error`。

## 六、图标

图标用原生形状绘制（`assets/icon-library/`），不得用图片。见该目录 `_README.md`。

## 六·续、图层顺序（`z_index`，v5.2 硬要求）

`build_pptx.js` **按 `z_index` 升序绘制**，页面计划里每个元素都必须声明：

| 层 | `z_index` | 谁在这一层 |
|---|---|---|
| L1 背景 | `0` | 整页背景图 + 蒙版（由 `image_path` 与母版处理，不写成元素） |
| L2 装饰 | `10–19` | 装饰色带、纹样、发光、粒子、`effects[]` 素材（默认 12） |
| L3 内容 | `20–29` | 正文 20、标签/指标 21、口径说明 22、图标 23、图表/表格 24、内容插图 25、模块小标题 26 |
| L4 标题 | `30–39` | 页面标题 30、副标题 31、封面大标题 32 |

约束：装饰层不得高于内容层（否则文字被压）；标题层必须高于内容层；背景层不要用元素模拟。`validate_plan.py` 会检查缺失、负值与层序倒挂，`detect_layout.py` 会检查是否真的遮挡。

## 七、可编辑性自检（交付前）

- [ ] `ppt/slideMasters/` 至少 1 个母版，且内页使用了母版版式
- [ ] 图表对象存在（`ppt/charts/chart*.xml`），可"编辑数据"
- [ ] 表格对象存在（`a:tbl`），可改单元格
- [ ] 无"整页图片"页（正文与标题都是文本框）
- [ ] 每页有 `notesSlide`
- [ ] 图标是形状而非图片
