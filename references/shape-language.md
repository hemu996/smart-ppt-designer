# 形状语言：把"默认矩形"换成"被设计过的轮廓"（v9.0.3）

**一句话**：矩形是 PowerPoint 的默认值，观众会读成"没设计"；换轮廓是最省力的"做过设计"信号。但换轮廓有两条路——**建语言**（少、统一、可跨页复用）与**加装饰**（多、杂、像学生作业）。本包只走第一条。

## 一、来源与去伪

来自短视频「大花生创赛ppt」拆解的《特殊形状设计技巧（通用版）》6 条。原文档把 6 条并列，实际是两类东西，必须拆开：

| 原技巧 | 判定 | 判断依据 |
|---|---|---|
| 1 圆角导航 + 主题小图标（奖杯/书本/向日葵） | 风格选择（高风险） | 语义图标一与主题不精确对应，立刻变培训课件 |
| 2 弧形色块做上下/左右分割 | 风格选择 | 弧形属"亲和/互联网"语法，进文献/档案类版面即拼贴 |
| 3 核心图配主题小装饰 | 风格选择（高风险） | 同上，且会让焦点从"图"跑到"装饰" |
| 4 左右卡片：浅底 + 主题色边框，卡片下加小标签 | **原理** | 讲的是用"底/边"承载层级，不是形状本身 |
| 5 折角形状做板块 | 风格选择 | 折角是一种语言，不是通用解 |
| 6 圆角大小统一；装饰不要太多、点睛即可 | **原理** | 全文唯一讲"控制"的一条 |

**结论**：6 条里 2 条原理、4 条风格。那 4 条共同服务于"显得努力"，不服务于"不像模板"——这两件事在评委眼里方向相反。

## 二、先分清目标，再决定用不用

- **目标 A「显得认真做了」**：校内初赛、班级评比、培训课件、家长会。圆角卡片 + 渐变 + 小图标确实有效。
- **目标 B「不像模板 / 不像 AI 生成」**：国赛省赛、专家评审、对外提案。同一套东西是**减分项**，因为它就是模板味的配方——大量同质创赛稿都长一个样，原因正是都在用这 4 条。

**本包默认目标 B。** 要按 A 打，必须用户明确说"要活泼/要亲和/校内用"。

## 三、目标 B 下的三条可用做法

1. **一份稿子只允许一套轮廓语法。** 全直角 / 全圆角 / 全切角 三选一，跨页统一，不混用。混用即拼贴，拼贴即 AI 味的来源。
2. **形状承载层级，不承载装饰。** 用"浅底 + 主题色边框/顶带"区分信息层级（原第 4 条），不要靠堆彩色圆角块制造丰富感。
3. **造型呼应题材，不用通用可爱件。** 中式/文献题材：册页切角、界格线、碑额弧；科技题材：直角 + 细导电轨。**禁用奖杯 / 向日葵 / 叶片 / 灯泡这类语义小图标**——它们与具体内容的对应永远不精确。

## 四、禁用清单（自检口径；不进红线表，避免红线数变化）

- ❌ 语义小图标（奖杯/书本/向日葵/灯泡/齿轮）充当装饰
- ❌ 用渐变填充做**装饰色块 / 卡片底**：投影仪色域窄易脏，且会把高饱和杂色推高（实测一册 38% 已超国金基准 33.7%）。
　例外（本包已有实现，属正当用途）：①封面整页渐变蒙版（压底色保白字对比度）；②图片 contain 后的左右补边渐变。这两种不算违规。
- ❌ 为"精致"加形状拉高 形/页——形/页 只能靠真实结构与装饰组（`decoration-sets.md`）达成，不能靠零散形状堆
- ⚠️ 若将来把弧形/折角/波浪加入 `SHAPE_TYPES`：同一页轮廓种类必须 ≤2，且全稿只用一套；否则就是拼贴

## 五、怎么落地（分清「配置已保证」与「要靠人看」）

本包**不新增校验脚本**，也不靠这几条去判分——先把已有的机制说清楚，避免重复造轮子：

1. **轮廓种类**：`validate_plan.py` 的 `SHAPE_TYPES` 只开放
   `rect / roundRect / ellipse / line / chevron / triangle / pentagon / diamond`。
   也就是说弧形、折角、波浪这类"风格形状"**当前不可用**——想用必须先扩 `SHAPE_TYPES`
   并同步 `build_pptx.js` 的绘制分支。**默认路径就是不混用**，无需额外检查。
2. **圆角半径统一**：已由 `assets/config.json` 的
   `creative_level.levels[<档位>].card_radius_in` 单值控制（off / conservative 0.18 /
   balanced 0.28 / expressive 0.45）。**全稿只有一个值，天然统一**，不要逐元素手写半径。
3. **渐变**：`build_pptx.js` 里 `gradientRect()` 仅有 3 处调用（封面蒙版 + 图片两侧补边），
   不存在"装饰色块渐变"通道。**只要不新增调用点，这条自动成立。**

真正需要人看、且机器判断不了的，是第四节前两条：**语义小图标**与**"加形状凑精致"**。
这两条的判据是"它与内容是否精确对应"，不是几何量。

## 六、实现备忘（重要：本包构建走 PptxGenJS，不是 python-pptx）

- 想用新轮廓，改**三处**才生效，缺一不可：
  1. `scripts/validate_plan.py` 的 `SHAPE_TYPES` 白名单；
  2. `scripts/build_pptx.js` 的形状绘制分支（`sh.shape_type` 映射到 pptxgenjs 对应方法）；
  3. `references/page-plan-schema.md` 的字段说明（否则写计划的人不知道能写）。
- 圆角半径不要写进元素，用 `creative_level` 档位统一控制。
- python-pptx 里 `ROUNDED_RECTANGLE / ARC / FOLDED_CORNER / WAVE` 等确实存在且可用，
  **但这与本包的 HTML→PPTX 构建链无关**；只在"直接改已生成 pptx"的场景才用得上，
  改完必须重跑交付自检。

## 七、与既有规范的关系

- 装饰仍然走 `decoration-sets.md`（页边距、真实 `<p:grpSp>`、`z_index` 10–19），**不要**用本节去新增页内散形状。
- 密度目标见 `gsl-alignment.md`；本节只回答"轮廓长什么样"，不回答"放多少"。
- 与 `anti-patterns.md` 第 33/34 条配套使用。
