# 叙事与篇幅规范（金字塔叙事 / 行动标题 / 时长驱动页数 / Q&A 预测）

对应规格 v8.6 验收项：金字塔叙事、行动标题（含「禁止短剧式标题」）、时长驱动页数、Q&A 预测、1 页样张确认。
配套落点：`config.json` 的 `narrative` 段、`scripts/validate_plan.py` 的对应检查、`scripts/score_deck.py` 的「叙事与正文」分项。

## 一、金字塔叙事（结论先行）

每页与每章都按同一顺序组织：

```
结论（一句话） → 3–5 个理由 → 证据（数据/案例/图表）
```

- 页级：`claim` 就是这一页的结论，必须能独立读懂；
- 章级：每章第一节先给结论，再展开理由；
- 语速：每页 **45–60 秒**（约 120–180 字讲稿），超出说明内容没收敛，应拆页或删。

## 二、行动标题（每页标题必须是完整结论句）

| 要求 | 说明 |
|---|---|
| 是"判断"，不是"栏目名" | ❌「项目背景」→ ✅「茶园面积扩张但亩产低于全国均值」 |
| 字数 | 建议 **8–30 字**；短于 8 字多半是栏目名 |
| 空标题黑名单 | 项目背景 / 方案设计 / 预期成效 / 目录 / 总结 / 概况 / 背景介绍 / 研究背景 / 项目介绍 / 实施方案（见 `config.json:narrative.title_blacklist`） |
| 校验 | `validate_plan.py` 对内页标题命中黑名单或过短时给出 warning |
| 不是「短剧金句」 | ❌「我最怕的不是计划不够漂亮」→ ✅「延期 2 周，风险集中在物料交付」（红线第 21 条，判据见 §二·1） |

例外：封面 / 章节过渡页 / 目录页 / 结尾页可以只用主题词（如章节名），不受「完整结论句」约束（规格 v8.6 修订；本包无独立目录页类型）。

### 二·1 禁止短剧式标题（规格 v8.4 红线第 21 条）

标题是"这一页的结论"，不是文案。**不得**写成文学化、情绪化的金句（"像短剧台词"）。

**判据（命中任一即返工）**：

| # | 判据 | 反例 |
|---|---|---|
| 1 | 第一人称情绪（我怕 / 我不怕 / 我见过 / 我们凭什么） | 「我最怕的不是计划不够漂亮」 |
| 2 | 口号式反问或感叹 | 「凭什么相信这个方案」「真的能行吗」 |
| 3 | 悬念 / 卖关子式表达 | 「没人告诉你的三个真相」 |
| 4 | 文学化比喻替代事实 | 「我们在风中点了把火」 |
| 5 | 只有态度、没有信息 | 「这一步，很关键」 |

**改法**：拆出「事实 + 结论」，用正式陈述句；动词开头或名词短语收束，能带数字就带数字。

- ❌「我最怕的不是计划不够漂亮」 → ✅「项目延期 2 周，风险集中在物料交付」
- ❌「凭什么相信这个方案」 → ✅「三项试运行数据支撑方案可行性」
- ❌「没人告诉你的三个真相」 → ✅「行业存在三个认知偏差，本方案逐一规避」

**校验落点**：`config.json:narrative.cliche_title_patterns` 黑名单句式；`validate_plan.py` 命中给 warning；
`score_deck.py` 的「叙事与正文」分项按命中扣分。**适用范围**：验收表「行动标题」只约束**内容页**；封面 / 章节过渡页 / 目录页 / 结尾页可用主题词，不受「必须是完整结论句」约束，但同样不宜写成情绪化短剧金句。

**豁免（规格 v8.6 修订）**：党建 / 政务类项目的正式政治表达（如「凝心聚力促振兴」「砥砺奋进谱新篇」）属规范表达，不算短剧金句；标题命中 `config.json:narrative.cliche_exempt_patterns` 时不再判为短剧金句。

### 二·2 正文语气：禁止 AI 味（规格 v8.6 红线第 22 条）

正文要**正式、朴实，像正经的项目汇报**，不能像小红书文案 / 小说 / 短剧台词。

**判据（命中任一即返工）**：

| # | 判据 | 反例 | 改法 |
|---|---|---|---|
| 1 | 小红书 / 口语化用语 | 「家人们，这套方案绝绝子」「谁懂啊，真的太顶了」 | 客观陈述：「三项试点数据均高于基准线」 |
| 2 | 断句太碎（短句堆叠、一行一句） | 「先看现状。再看痛点。最后给方案。」 | 合并成完整句，用分号或逗号串联 |
| 3 | 每段结尾都空泛升华（商业 / 科技类项目） | 每段都以「未来可期」「我们坚信」「携手共创」收尾 | 结尾落在事实与下一步动作上；党建 / 政务 / 乡村振兴类项目的正常结尾升华属规范表达，不算 AI 味 |
| 4 | 空泛动词堆砌 | 「赋能全链路、打造新引擎、构建生态、引领未来」 | 换成可核对的动词与数字：「把交付周期从 45 天压到 30 天」 |

**豁免（规格明确规定）**：「赋能 / 打造 / 构建 / 引领」在**党建 / 政务 / 乡村振兴**类项目中属正式政治语言，可正常使用；
**科技 / 商业类项目**避免空泛使用。同一语境下，「未来可期 / 我们坚信 / 携手共创」这类**正常结尾升华属规范表达**（`config.json:body_style.escalation_exempt_in_context`），只有商业 / 科技类项目才按空泛升华告警（规格 v8.6 修订）。判定依据来自 `brief_intent`（deck_title / communication_goal / audience）与 `design_brief.sections`
里的语境词，命中则在 `config.json:body_style.context_exempt_keywords` 中豁免。

**校验落点**：`config.json:body_style` 的三份词表；`validate_plan.py` 逐页给出 warning / info；
`score_deck.py` 的「叙事与正文」分项按命中扣分。正文的正式度属判断项，脚本只覆盖可枚举的语料，最终仍由人工终审。

## 三、时长驱动页数

| 汇报时长 | 建议页数 | 依据 |
|---|---|---|
| 10 分钟 | 10–12 页 | 规格第七章 |
| 15 分钟 | 15–20 页 | 同上 |
| 45 分钟 | 25–30 页 | 同上 |

- 计算口径：`config.json:narrative.pages_per_minute = 1.5`（≈1.5 页/分钟）；
- 页面计划里写 `brief_intent.duration_min`，`validate_plan.py` 会在候选页数与推算值偏差 >30% 时给 warning。

## 四、Q&A 预测

- 在**结尾页或末页的讲者备注**里附 **5–10 条**评委可能问的问题，每条给一句话答点；
- 问题要覆盖：数据口径、可行性、成本、风险、竞品差异、团队能力；
- 备注里用固定小标题 `Q&A 预测：` 开头，便于检测与复用（`config.json:narrative.qa_min_questions = 5`）。

## 五、1 页样张确认（批量生成前）

1. 先只生成 **第 1 页封面**（可用 `build_pptx.js` 对单页候选或最小计划构建）；
2. 交用户确认**风格 / 配色 / 布局**；
3. 不满意 → 调视觉系统或布局后重出样张，**最多 3 次**；
4. 确认后再批量生成全套 —— 这是最省返工的一步，不要跳过。

## 六、自检清单

- [ ] 每页 `claim` 是一句结论，不是栏目名；
- [ ] 内页标题通过"行动标题"检查（≥8 字、不在黑名单、不是短剧式金句）；
- [ ] 页数与 `duration_min` 匹配（偏差 <30%）；
- [ ] 结尾页备注含 5–10 条 Q&A 预测；
- [ ] 批量生成前出过 1 页封面样张并获得确认。
