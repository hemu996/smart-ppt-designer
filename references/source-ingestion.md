# 多源材料解析指南

输入不一定是纯文本：PDF、DOCX、网页、已有 PPT 都可能。第 1 步"材料解析"就是把它们变成可用的**论点 + 数据 + 口径**。

## 一、支持与方式

| 输入 | 方式 |
|---|---|
| 纯文本 / Markdown | 直接读，按标题层级切段 |
| PDF | `python scripts/parse_source.py --input x.pdf --out output/source.md`（文本型 PDF 走文本抽取；扫描件走图像/OCR 路线，见下） |
| DOCX | `python scripts/parse_source.py --input x.docx --out output/source.md`（正文 + 表格；跳过页眉页脚与批注） |
| HTML | `python scripts/parse_source.py --input x.html --out output/source.md`（去导航/广告节点，保留标题与正文） |
| 已有 PPT/PPTX | `python scripts/parse_source.py --input x.pptx --out output/source.md`（按页抽取标题/要点，并可作为**风格提取**样本，见 `design-brief.md`） |

`parse_source.py` 只做**结构与文字抽取**，不做总结；总结由模型在第 1 步完成。

## 二、从材料到论点（第 1 步的三种产出）

1. **核心论点 3–5 条**：每条一句话，是可被反驳的主张（不是"本次汇报包含三部分"这类空话）；
2. **关键数据表**：数值 + 单位 + 时间 + 样本量/来源，逐条带口径。缺口径的数据**不许进 PPT**，先补；
3. **素材缺口清单**：哪些页需要图、哪块数据还缺、哪些说法需要用户确认。

## 三、口径纪律（评委最常追问的点）

| 必须写清 | 反例（不许出现） |
|---|---|
| 时间范围 | "覆盖 1 万人次" |
| 样本量/统计范围 | "满意度 4.8" |
| 来源（问卷/系统/公开统计） | "效果显著" |
| 与基线的对比方式 | "提升明显" |

写法示例：`覆盖 1.03 万人次/月（2026.08–10，3 个街道社区站点，来源：站点台账）`。

## 四、不照抄

- 材料里的段落不能整段搬进页面：页面只放**结论与关键数字**，解释放备注（`notes`）；
- 已有 PPT 的文案只作**素材**，不能作为成品页直接复制（除用户明确要求"保留原版面"）；
- 引用他人材料必须标注来源；不确定出处的数据标"待核"并在交付说明里列出。

## 五、扫描件与不可解析材料

1. 优先尝试文本抽取；判据是抽取结果里"有效字符数 < 200 或乱码比例高"；
2. 扫描件转图（PDF→图片）后走视觉识读，把结果写成 Markdown 源材料**并注明"由图像识读，未逐字校对"**；
3. 仍无法解析时：向用户说明缺口、需要哪几页的原文字，**不要编造内容**；
4. 解析产物统一放 `output/source.md`，作为第 2–6 步的唯一事实来源。

## 六、自检

- [ ] `output/source.md` 存在，且论点与数据都能回溯到材料
- [ ] 每条数据带口径（时间/样本/来源）
- [ ] 缺口清单已写，且没有"猜"出来的内容
- [ ] 扫描件识读结果已标注校对状态
